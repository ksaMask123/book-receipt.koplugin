v0.2.3+hotfix2 2026-09-08

站台样式按钮恢复可用（CONTINUE / 书籍卡片，未升版，仅 G 盘改动）

修复 问题现象

实机反馈：站台样式的「继续阅读」按钮点了没反应——只关闭小票，什么都没发生， crash.log 里也查不到任何线索。

前提纠正 所谓"原设计功能"其实并不存在

回查母补丁 2-book-receipt-shortcut-and-lockscreen.lua（6833 行）： paintHomeStation（L6299–6500）内检索 CONTINUE / 继续阅读 零命中； 全文件检索 addAction / action_hits / hit_books 零命中； L4481 quicklookbox:onTap() return self:onClose() —— 补丁版站台是纯看板，点哪都是关闭。 现在的 CONTINUE 按钮是插件化时照母插件 readingline 搬来的新增元素， 因此本次对齐的是母插件那套语义（继续阅读 = 打开当前书，点卡片 = 打开该书）。

根因 三层故障链：只修第一层等于白修

L1（致命）：station.lua L455、main.lua L439 两处 require("frontend/ui/utils") —— 真机 frontend/ui/ 下根本没有 utils.lua（已 ls 实锤）， openBookThroughFileManager 是母插件 rl_shelf_utils.lua L205 的私有函数， 移植时被误当成 KOReader 前端通用工具。station 那处还被 pcall 包着 → 纯静默失效。
L2（数据）：station.lua L236 路径靠书名反查，两边标题来源不同 （coverbrowser 抽取 vs 打开时显示名），对不上就是 nil → 就算 L1 修好， main.lua 判空后仍只关闭。
L3（语义）：station.lua 的"正在阅读"= 统计库最后读的一本， 而 statistics 50 次翻页才落库 → 刚换书时是上一本书 → 修好 L1 会打开错书（比失效更糟）。

  • 否则 UIManager:nextTick 内 pcall：优先 FileManager 实例:openFile()， 没有则 ReaderUI:showReader()（两者均已核实存在于真机）
  • 失败不再静默：logger.warn(LOG_TAG, ...) + InfoMessage 提示

  • 新增 md5→文件路径懒加载映射：书名反查失败时兜底， 照抄官方 statistics.koplugin main.lua L828 的 hasSidecarFile → partial_md5_checksum 快路径 + util.partialMD5 兜底

  • 按钮回调与开书两处 pcall 均补 logger.warn(LOG_TAG, ...)
  • 保持"先 onClose 再回调"顺序不变（栈已清空，比母插件"回调内关闭"更稳）
边界 屏保路径不覆盖

锁屏/屏保下站台由 ScreenSaverWidget（modal）承载，点击不走 quicklookbox:onTap，本就不响应；改动风险高，本次不涉及。 另：当前书未落库时，进度/时长会显示 0 或「—」，这是诚实表现，优于显示上一本书。

v0.2.3+hotfix 2026-09-08

单书行程票「显示错书」修复（档位 A+B，未升版，仅 G 盘改动）

修复 问题现象（KPW4 用户反馈）

手势唤出单书行程票后，生成的不是当前书籍的小票（书名/封面/进度/行程全是上一本书）， 「点好几次、隔段时间」才变成当前书。

根因 统计库里没有当前书 → 静默回退成「库里最新一条」

ui.doc_props.display_title 一直是对的，但单书票要用书名去 statistics 库匹配阅读记录； 上游 statistics.koplugin 每 50 次翻页才 insertDB 落库（MAX_PAGETURNS_BEFORE_FLUSH = 50）， 新书刚翻开就唤出必然匹配不到 → 原代码回退 rows[#rows]（= 上一本书），整票画成别人的书。 「隔段时间才对」正是等落库；反复唤出不触发落库。与设备无关，换书后 50 页内唤出必触发。

方案 A 不再回退，零数据占位

三轮匹配（md5 / 书名精确 / 子串）全落空时，用当前书名构造一条零数据记录， 票面仍是当前书（封面也按当前书名取），只是统计为空：

  • 书名下方提示行改为「本书暂无阅读记录 · 继续阅读或待机后自动统计」

  • render() 新增第 8 个参数 book_md5（仅 book 票型传入，其余票型不受影响）
  • 匹配顺序改为 md5 → 书名精确 → 子串，md5 命中即锁定，杜绝重名/书名改动串书
  • 新增匹配方式日志：[BookReceipt] 单书票匹配: md5|title|fuzzy|none(空数据)，便于按 LOG_TAG 查 crash.log

v0.2.3 2026-09-07

月票：日期数字被封面遮挡（顶部预留日期条）

修复 问题现象

用户真机反馈：一天读 2 本时，日期数字上半截可见、下半截与书籍封面重叠， v0.2.2 设计的「白底小牌」在该情况下未起到遮挡隔离作用。

根因 封面顶边压在数字上

按 KPW3 竖屏实测缩放（s=1.030 / sy=1.317，格子真实 107.7×112.2 像素）反推： 双书并排时封面顶边位于格子顶部下方约 13.9 虚拟像素处，而日期白牌底边在 17 处， 两者几乎相切、存在约 0.1 像素的重叠；单本时封面更是垂直占满整个格子 （顶边即格子顶），同样压住数字。白底牌尺寸本就紧贴数字边缘，一旦封面顶边上移即被盖过。

方案 仅 2 本及以上让出日期条，单本保持占满

按用户指示「把双书情况下的书籍封面整体下移，露出数字」，并按用户后续取舍 「只有 2 本及以上才下移、单本保持占满」定稿：

  • 新增常量 DAY_BAR_H = 16（虚拟坐标）；按当日书本数决定预留量： bar = (n >= 2) and DAY_BAR_H or 0
  • 封面盒子：by = cy + CELL_PAD + bar，bh 同步减去 bar
  • 单本 bar = 0，封面垂直铺满整格（尺寸维持 75×104，不缩小）； 日期白牌在封面之后绘制，仍覆盖于其上
  • 占位灰牌共用同一盒子，与封面保持对齐
  • 日期白牌加大并随位数自适应：一位数宽 19、两位数宽 25，高度统一 16， 数字仍绘制在 cx+6, cy+5，与无阅读日的日期数字位置完全一致
影响 最终尺寸（真实像素）
  • 单本：75×104（占满格子，与改造前一致，不缩小）
  • 双书并排：各 48×67 —— 尺寸与下移前完全一致，仅整体下移让出日期条
  • 扇形叠放（3 本及以上）：每张 52×72
验证 几何桩测试全绿（PASS=18 / FAIL=0）
  • 多本日（2 本 / 4 本）：封面顶边 ≥ 白牌底边，零重叠
  • 单本日：封面顶边贴合格子内沿（误差 ≤2px），确认恢复占满且尺寸回到 75×104
  • 所有格子：白牌绘制序号均大于同格封面（绘制顺序在后）

  • 根因：书名渲染（book.lua）单行直出且宽度估算按「全角字宽=字号」计算，用户字体（小熊甜茶心动体）实际字宽更大，估算系统性偏小
  • 修复：新增 splitTitleLines，书名最多两行（行宽 460 虚拟单位，止步于「当前进度」区 x=776 之前）；切行用 painter.M（TextWidget 实测渲染宽度），不依赖字宽估算；超两行末行减字加省略号截断
  • 配套：作者行 y=282 → 308，为第二行书名让位；与 facts 区（y=368）无冲突
新增单书行程票封面（真机需求）
  • 封面获取优先级：① 书籍元数据封面（rl.getBookCoverFromPath：CoverBrowser 缓存 → DocumentRegistry 提取，与站台样式同链路）→ ② Kindle 原生侧车缩略图（<dir>/<base>.sdr/<base>-thumbnail_te.png 等 4 种候选）→ ③ 均无时回退原竖排书名占位框
  • 书名→文件路径映射：遍历阅读历史（readhistory），CoverBrowser 书库信息反查书名，未装时退化为文件名匹配；模块级缓存 60 秒防重复构建
  • 封面按占位框（148×125）内 0.72 宽高比居中绘制；全程 pcall 保护，失败静默回退占位
修复阅读时长文本过长挤压右侧字段（真机反馈，全部票型）
  • 现象：年票「18小时49分」与相邻「ACTIVE DAYS 15天」挤压重叠；日/周/月/单书/屏保票同源问题
  • 修复：rlTime（rl_reference.lua，全部票型唯一时长出口）统一换算为仅「小时」单位：<60s → 「0小时」；<24h → 1 位小数（如 18.8小时，去尾 .0）；≥24h → 整数（如 50小时）
验证语法 + 逻辑桩测试

  • 逻辑桩测试：rlTime 11 用例全 PASS（含 67746s→18.8小时、86400s→24小时边界）；splitTitleLines 4 用例全 PASS（1.5 倍宽系数拆两行且行宽 ≤460、1.0 倍宽单行、60 字两行封顶+省略号、空书名）
